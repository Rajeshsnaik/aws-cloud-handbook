# 🔵 Amazon EventBridge

![aws](./event-bridge.png)

**Amazon EventBridge** is a **fully managed serverless event bus service** that connects AWS services, custom applications, and SaaS applications using events.

Instead of one application directly calling another, EventBridge receives events and routes them to the appropriate destination automatically.

It enables you to build **event-driven architectures** without managing messaging infrastructure.

---

# 🔵 What is an Event?

An **Event** is simply a notification that something has happened.

Examples:

- EC2 instance started
- EC2 instance stopped
- S3 file uploaded
- RDS database created
- IAM user created
- CodePipeline completed
- CloudWatch alarm triggered

Whenever an action occurs in AWS, an event can be generated.

---

# 🔵 What is an Event Bus?

An **Event Bus** is a central place where events are received before being routed to their destination.

Think of it as a traffic controller.

```
Event

↓

Event Bus

↓

Target
```

Instead of applications communicating directly, they send events to the Event Bus.

---

# 🔵 How Amazon EventBridge Works

Amazon EventBridge follows a simple workflow.

```
Event Source

↓

Amazon EventBridge

↓

Rule

↓

Target
```

Example

```
Amazon S3

↓

Object Uploaded

↓

EventBridge

↓

Rule

↓

AWS Lambda
```

When a file is uploaded to S3, EventBridge automatically triggers the Lambda function.

# 🔵 Rules

Rules determine what should happen when an event arrives.

A rule contains:

- Event Pattern
- Target

Example

```
If

EC2 State = Stopped

↓

Send Notification
```

---

# 🔵 Event Pattern

An **Event Pattern** filters incoming events.

Only matching events trigger the rule.

Example

```json
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["stopped"]
  }
}
```

This rule only matches EC2 instances entering the **Stopped** state.

# 🔵 EventBridge vs SNS vs SQS

| Feature          | EventBridge    | SNS               | SQS                     |
| ---------------- | -------------- | ----------------- | ----------------------- |
| Main Purpose     | Event Routing  | Notifications     | Message Queue           |
| Communication    | Event Driven   | Publish-Subscribe | Queue Based             |
| Ordering         | Not Guaranteed | Not Guaranteed    | FIFO Available          |
| Multiple Targets | Yes            | Yes               | No                      |
| Event Filtering  | Advanced       | Basic             | No                      |
| Scheduling       | Yes            | No                | No                      |
| Stores Messages  | No             | No                | Yes                     |
| Best For         | Event Routing  | Notifications     | Asynchronous Processing |

# 🔵 When Should You Use EventBridge?

Use EventBridge when:

- AWS services need to communicate automatically.
- You want event-driven automation.
- You need scheduled jobs.
- You want to connect multiple AWS services.
- You need event filtering.
- You need SaaS integrations.

---

# 🔵 When Should You Use SNS?

Use SNS when:

- You need notifications.
- You want to send emails or SMS.
- One message should reach multiple subscribers.

---

# 🔵 When Should You Use SQS?

Use SQS when:

- Applications process tasks asynchronously.
- Messages need to be stored until processed.
- Producers and consumers should be decoupled.

# 🔵 Summary

- Amazon EventBridge is a fully managed serverless event bus service.
- It connects AWS services, custom applications, and SaaS applications using events.
- Events are received by an Event Bus, filtered using Rules, and delivered to Targets.
- EventBridge supports scheduling, event filtering, event archiving, replay, and cross-account event sharing.
- Common targets include AWS Lambda, Amazon SNS, Amazon SQS, Step Functions, and CloudWatch Logs.
- It is commonly used for automation, event-driven architectures, infrastructure monitoring, CI/CD workflows, and scheduled tasks.
